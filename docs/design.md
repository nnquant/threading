# Threading 设计说明

## 要解决的问题

同时为多个组织做多个策略项目，每个项目里又有多条策略线并行推进。难点不在“记任务”，而在：

- 线太多，**不知道哪条线停了、哪条在等人、哪条缺了下一步**；
- 在组织和项目之间来回切换，**回到一条线时想不起它走到哪、为什么这么做**；
- 研究类工作的进度用百分比描述不准确，**“还没想清楚”和“只剩执行”是两种完全不同的状态**；
- 同时开的线越来越多，**没有人提醒“该收一收了”**。

## 调研：流行方案各自擅长什么

| 方案 | 核心做法 | Threading 借鉴了什么 |
| --- | --- | --- |
| [Linear](https://linear.app/docs/linear-method) | 层级为 Workspace → Team → Project → Issue；项目有健康度（On track / At risk / Off track）和带健康度的[进展更新](https://linear.app/docs/initiative-and-project-updates)；键盘优先、Ctrl+K 命令面板 | 项目健康度与“进展”记录；命令面板；键盘操作；克制的列表密度 |
| Basecamp《Shape Up》 | 用**山丘图**表示不确定性：上坡是“还在摸索”，下坡是“只剩执行” | 每条策略线一个山丘位置，项目页有可拖动的山丘图 |
| GTD（Getting Things Done） | 每个进行中的项目都必须有明确的**下一步**；单独的**等待清单**；**每周回顾** | 下一步待办、“缺少下一步”提醒、等待对象与等待天数、周回顾流程 |
| Kanban | 看板按阶段排列，**限制在制品（WIP）** | 按研发阶段的看板，拖动换阶段；进行中上限提醒 |
| QuantConnect 等量化平台 | 策略按证据逐级推进：研究 → 回测 → 模拟 → 实盘 | 六个固定阶段：构想、研究、回测、模拟、实盘、退役；策略线上记关键指标 |
| Notion / ClickUp / Plane | 高度可定制的数据库与多视图 | 只取“同一份数据多种视图”（列表 / 看板 / 山丘图 / 时间线），刻意不做自定义字段，避免变成维护负担 |

结论：通用工具要么偏团队协作（Linear、Asana、Plane），要么过于自由（Notion）。一个人横跨多组织管理研究线，更需要**跨组织的注意力视图**和**研究进度的正确表达**，所以做成本地优先的单人桌面工具。

## 模型

```text
组织 Organization ── 客户、基金或自营研究
└─ 策略项目 Project ── 健康度、状态、目标、目标日期、进展
   └─ 策略线 Thread ── 阶段、状态、优先级、山丘位置、等待对象、标签、指标、说明
      ├─ 下一步 Todo ── 第一条未完成的就是“下一步”，可设截止日期
      └─ 记录 Entry ── 笔记、决策、结果；阶段/状态变更自动记录
```

两个正交维度刻意分开：

- **阶段 stage**：这条线在研发流程的哪一步（构想 → 研究 → 回测 → 模拟 → 实盘 → 退役）。
- **状态 state**：我现在对它的投入（进行中 / 等待 / 搁置 / 已结束）。

## 视图

- **焦点**：跨所有组织，只列需要处理的事——七天内到期的下一步、等待中的线（按等待时长）、停滞的线（超过设定天数没有推进）、缺少下一步的线、有风险或偏离的项目，以及超过进行中上限的提醒。
- **全部策略线**：列表（按项目 / 阶段 / 状态 / 优先级分组）或按阶段的看板。
- **组织**：项目一览，每个项目的进行中策略线沿阶段线分布。
- **项目**：策略线、山丘图、动态（项目进展与所有策略线记录）。
- **周回顾**：逐条过一遍进行中和等待中的线，确认阶段、山丘位置和下一步，记一笔，标记已回顾。
- **策略线详情**：右侧面板，所有属性、下一步、指标、说明和时间线都在这里。

## 视觉

沿用 Dropping 的语言：白底墨色、Noto Sans、13px、细线分隔、4px 圆角、自绘标题栏和状态栏。颜色只用于语义（健康度、逾期、停滞）和组织色块。唯一的“记忆点”是**线**：阶段用一根带结点的细线表示，时间线上的每条记录也是线上的一个结。

## 前后端分工

- 前端（`src/`）：React 19 + TypeScript，只通过 [`src/bridge.ts`](../src/bridge.ts) 调用后端命令，用后端返回的 `Change` 合并状态。浏览器预览使用 [`src/preview.ts`](../src/preview.ts) 中遵循同一契约的内存实现和演示数据。
- 后端（`src-tauri/`）：Rust + Tauri 2 + SQLite，规则见 [backend-contract.md](backend-contract.md)，实现说明见 [backend-notes.md](backend-notes.md)。
